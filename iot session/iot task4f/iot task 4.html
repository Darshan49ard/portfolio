IoT Session — Task 4: Forge Web Dashboard

1. Overview

Objective

The goal of this task is to create a responsive three-page dashboard for Forge using HTML, CSS, and JavaScript. The dashboard allows users to view sensor readings and control a bulb from different screen sizes.

Problem Being Addressed

In earlier tasks, the ESP32 was controlled through a local web page, an Adafruit IO dashboard, and Google Assistant. None of these provided Forge with its own dedicated interface. This task creates a single, clean place for sign-in, live monitoring, bulb control, mode selection, and data download.

This interface is built before the hardware is connected. Firebase is set up through a placeholder configuration file, and the real values are added in Task 5.

Project Summary

This project is a three-page web app: a landing page, a login page, and a dashboard. The dashboard displays live temperature, humidity, and light values, includes an animated bulb toggle, provides manual and automatic modes, has a light-sensitivity slider, shows a history table, and supports CSV export.

Basic operation: User → Landing Page → Login Page → Dashboard → Firebase Realtime Database

2. Concepts

Dashboard

The web page used to see the sensor data and control the bulb. Here it is a small three-page web app, built on its own before any hardware is connected.

Three-Page Web App

A landing page announcing Forge, a login page, and the dashboard itself.

HTML, CSS and JavaScript

The three languages of every web page: HTML is the structure, CSS is the look, JavaScript is the behaviour. Forge uses only these, with no framework.

State Management

Keeping track of what the page currently knows, for example whether the bulb toggle is a manual command or the automatic mode's decision.

Mode Selector

The control that switches between manual and automatic.

Light-Sensitivity Slider

The slider that sets the threshold (0–4095) used in automatic mode.

History Table

The list of the latest recorded readings.

CSV Export

One click downloads the recorded temperature, humidity and light as a spreadsheet file.

Input Validation

Checking what a user types before it is used, so bad values never reach the database.

Loading and Error States

What the page shows while data is still arriving, and what it says when something goes wrong, instead of a blank screen.

Responsive CSS

Styles that adapt to the screen size. The dashboard was tested on phone, tablet and desktop.

Transition Animation

A short smooth change between two states. Without it the toggle felt dead; with it the same response felt instant.

Perceived Performance

How fast something feels rather than how fast it is. Users do not care about the stack, they care that clicking ON turns the light on.

3. System Design

System Architecture

The complete system contains four major elements:

User → Web Dashboard (Browser) → Firebase (Auth + Realtime Database) → ESP32 → Bulb

In this task only the first two parts are built and checked. The Firebase and ESP32 connection is completed in Task 5.

Data Flow

  1. The user opens the landing page and selects Sign in.
  2. The login page validates the email and password and signs in with Firebase Authentication (or Google).
  3. If the user is already signed in, the login page redirects straight to the dashboard.
  4. The dashboard checks the sign-in state and redirects to the login page if nobody is signed in.
  5. Real-time listeners read the bulb state, settings and latest 20 readings from the database.
  6. The page redraws cards, bulb, mode and history table whenever data changes.
  7. The user toggles the bulb, changes the mode or moves the slider; the change is written to the database.
  8. The user can export up to the latest 5000 readings as a CSV file.

6. Dashboard Configuration

The dashboard is the main interface of the system and contains the following elements:

ElementFunction
Status lineShows Connecting, Live (updated N s ago) or Device offline
Sensor cardsTemperature (°C), humidity (%), light (0–4095)
Bulb cardAnimated bulb icon and ON/OFF toggle switch
Mode selectorManual or Automatic
Light-sensitivity sliderThreshold from 0 to 4095 used in automatic mode
History tableLatest 20 readings: time, temperature, humidity, light, bulb
Export CSV buttonDownloads up to the latest 5000 readings

Dashboard Operation

  • Manual mode: the toggle shows and sets what the user asks for.
  • Automatic mode: the toggle is disabled and shows what the relay is actually doing; the bulb switches on when the light reading is above the threshold.
  • Slider: the value is validated to be between 0 and 4095 (the ESP32 ADC range) before it is saved.

The dashboard reads and writes under the signed-in user's own path:

users/<uid>/settings      { mode: "manual" | "auto", threshold: 0–4095 }
users/<uid>/readings/<ts> { temperature, humidity, light, relay }

      signInWithEmailAndPassword(auth, email, password).catch(fail);
    });

    google.addEventListener("click", () => {
      msg.textContent = "";
      busy(true);
      signInWithPopup(auth, new GoogleAuthProvider()).catch(fail);

<script type="module">
  import { auth, db } from "./firebase-config.js";
  import { onAuthStateChanged, signOut } from "https://www.gstatic.com/firebasejs/10.12.2/firebase-auth.js";
  import { ref, onValue, set, update, get, query, limitToLast } from "https://www.gstatic.com/firebasejs/10.12.2/firebase-database.js";

  const $ = (id) => document.getElementById(id);
  let base = "", started = false;
  let bulbWanted = false, mode = "manual", threshold = 2000, latest = null, history = [];

  const say = (text) => { $("err").textContent = text || ""; };
  const readError = () => say("Cannot read your data. Check that you are signed in and that the security rules are published.");
  const writeError = () => say("That change could not be sent. Check your connection and try again.");
  const num = (v, digits) => (typeof v === "number" && isFinite(v)) ? v.toFixed(digits) : "--";

  // sign in guard
  onAuthStateChanged(auth, (user) => {
    if (!user) { location.replace("login.html"); return; }
    base = "users/" + user.uid;
    $("who").textContent = user.email || "";
    start();
  });
  $("out").addEventListener("click", () => signOut(auth));

  // live listeners: the page updates itself when the data changes
  function start() {
    if (started) return;
    started = true;
    onValue(ref(db, base + "/bulb"), (snap) => { bulbWanted = snap.val() === true; render(); }, readError);
    onValue(ref(db, base + "/settings"), (snap) => {
      const v = snap.val() || {};
      mode = v.mode === "auto" ? "auto" : "manual";
      if (typeof v.threshold === "number") threshold = v.threshold;
      render();
    }, readError);
    onValue(query(ref(db, base + "/readings"), limitToLast(20)), (snap) => {
      const rows = [];
      snap.forEach((child) => { rows.push({ ts: Number(child.key), ...child.val() }); });
      rows.sort((a, b) => a.ts - b.ts);
      history = rows;
      latest = rows.length ? rows[rows.length - 1] : null;
      render();
    }, readError);
    setInterval(renderStatus, 1000);
  }

  // drawing
  function render() {
    say("");
    $("temp").textContent = latest ? num(latest.temperature, 1) : "--";
    $("hum").textContent = latest ? num(latest.humidity, 0) : "--";
    $("light").textContent = latest ? num(latest.light, 0) : "--";
    const on = mode === "auto" ? !!(latest && latest.relay) : bulbWanted;
    $("toggle").checked = on;
    $("toggle").disabled = mode === "auto";
    $("bulb").classList.toggle("on", on);
    $("bulbNote").textContent = mode === "auto" ? "Automatic - the light sensor decides" : (on ? "On (manual)" : "Off (manual)");
    document.querySelectorAll("[data-mode]").forEach((b) => b.setAttribute("aria-pressed", String(b.dataset.mode === mode)));
    if (document.activeElement !== $("range")) { $("range").value = threshold; $("rangeOut").textContent = threshold; }
    const body = $("rows");
    body.textContent = "";
    if (!history.length) {
      const tr = document.createElement("tr"), td = document.createElement("td");
      td.colSpan = 5; td.className = "status"; td.textContent = "Waiting for the first reading...";
      tr.append(td); body.append(tr);
    }
    history.slice().reverse().forEach((r) => {
      const tr = document.createElement("tr");
      [new Date(r.ts * 1000).toLocaleTimeString(), num(r.temperature, 1), num(r.humidity, 0), num(r.light, 0), r.relay ? "ON" : "OFF"]
        .forEach((text) => { const td = document.createElement("td"); td.textContent = text; tr.append(td); });
      body.append(tr);
    });
    renderStatus();
  }

  function renderStatus() {
    const el = $("status");
    if (!latest) { el.classList.remove("live"); el.lastChild.textContent = "Waiting for the first reading..."; return; }
    const age = Math.max(0, Math.round(Date.now() / 1000 - latest.ts));
    const live = age < 15;
    el.classList.toggle("live", live);
    el.lastChild.textContent = live ? "Live - updated " + age + " s ago" : "Device offline - last reading " + (age < 3600 ? Math.round(age / 60) + " min" : Math.round(age / 3600) + " h") + " ago";
  }

  // controls
  $("toggle").addEventListener("change", (e) => {
    if (mode === "auto") return;
    set(ref(db, base + "/bulb"), e.target.checked).catch(writeError);
  });
  document.querySelectorAll("[data-mode]").forEach((b) => b.addEventListener("click", () => {
    update(ref(db, base + "/settings"), { mode: b.dataset.mode }).catch(writeError);
  }));
  $("range").addEventListener("input", (e) => { $("rangeOut").textContent = e.target.value; });
  $("range").addEventListener("change", (e) => {
    const v = Math.round(Number(e.target.value));
    if (!(v >= 0 && v <= 4095)) return;
    update(ref(db, base + "/settings"), { threshold: v }).catch(writeError);
  });

  // one-click CSV export (up to the latest 5000 readings)
  $("csv").addEventListener("click", async () => {
    const btn = $("csv");
    btn.disabled = true;
    try {
      const snap = await get(query(ref(db, base + "/readings"), limitToLast(5000)));
      const rows = [["time_iso", "unix_time", "temperature_c", "humidity_percent", "light_0_4095", "bulb"]];
      snap.forEach((child) => {
        const v = child.val();
        rows.push([new Date(Number(child.key) * 1000).toISOString(), child.key, v.temperature, v.humidity, v.light, v.relay ? "ON" : "OFF"]);
      });
      if (rows.length === 1) { say("There are no readings to export yet."); return; }
      const blob = new Blob([rows.map((r) => r.join(",")).join("\n")], { type: "text/csv" });
      const a = document.createElement("a");
      a.href = URL.createObjectURL(blob);
      a.download = "forge-readings.csv";
      a.click();
      URL.revokeObjectURL(a.href);
    } catch (err) {
      say("Could not export the data. Try again.");
    } finally {
      btn.disabled = false;
    }
  });
</script>
</body>
</html>

11. Explanation of Important Code Sections

Sign-In Guard

onAuthStateChanged(auth, (user) => {
  if (!user) { location.replace("login.html"); return; }
  base = "users/" + user.uid;
  start();
});

The dashboard redirects to the login page if nobody is signed in. Each user's data lives under their own users/<uid> path.

Real-Time Listeners

onValue(ref(db, base + "/bulb"), (snap) => { bulbWanted = snap.val() === true; render(); }, readError);

onValue keeps the page up to date without a refresh. The same pattern is used for settings and the latest 20 readings.

Manual vs Automatic State

const on = mode === "auto" ? !!(latest && latest.relay) : bulbWanted;
$("toggle").disabled = mode === "auto";

In manual mode the toggle shows what the user asked for. In automatic mode it shows what the relay is actually doing and is disabled.

Input Validation

if (!/^\S+@\S+\.\S+$/.test(email)) { msg.textContent = "Enter a valid email address."; return; }
if (password.length < 6) { msg.textContent = "The password is at least 6 characters."; return; }

Bad values are caught on the page and a friendly message is shown, instead of sending them on.

Loading and Error States

const readError = () => say("Cannot read your data. Check that you are signed in and that the security rules are published.");

The status line shows Connecting, Waiting for the first reading, Live, or Device offline. Read and write failures show a clear message instead of a blank screen.

Threshold Slider

if (!(v >= 0 && v <= 4095)) return;

The threshold is only saved when it lies inside the ESP32 ADC range.

CSV Export

const snap = await get(query(ref(db, base + "/readings"), limitToLast(5000)));

Reads up to the latest 5000 readings, builds a CSV file in the browser and downloads it as forge-readings.csv.

Responsive and Reduced-Motion CSS

@media (max-width:760px){.grid{grid-template-columns:1fr}.value{font-size:38px}}
@media (prefers-reduced-motion:reduce){*{transition:none!important}}

Cards stack below 760 px, and transitions switch off when the system asks for reduced motion.

13. Challenges & Fixes

Challenge 1 — Blank Page and Red Console Error

Problem: The page was blank with a red error in the browser console. Solution: The page had been opened straight from a file. It was run through the local server and opened at http://localhost:8000.

Challenge 2 — Styling Missing

Problem: The pages appeared without styling. Solution: style.css was not in the same folder as the pages. All six files were kept together in forge-dashboard.

Challenge 3 — Nothing Clickable

Problem: Nothing on the page responded to clicks. Solution: A script had failed to load. The browser console was opened and the first red error was read and fixed.

Challenge 4 — Dashboard Felt Broken Without Animation

Problem: The first version of the dashboard had no transition animations, and a plain instant switch felt dead. Solution: Smooth transitions were added to the bulb and toggle. A response that took a full second then felt instant, while a 10x faster change with no feedback felt sluggish.

14. Learning Reflection

This task made me think about users for the first time. Underneath the simple three-page interface sat real complexity: Firebase listeners, state management, validation, error handling and responsive layouts. The whole point was that nobody should ever see it. People just want the cards to update, the toggle to feel smooth, the mode switch to do the right thing, and the export button to give them their data.

My favourite lesson came from an animation. The version without transitions felt broken, and the version with them felt instant even though it was technically slower. This taught me more about perceived performance than any optimization guide: users do not care about the stack, they care that clicking ON turns the light on, and great engineering is the part they never see.

I measured, tested on phone, tablet and desktop, and kept a performance bar in mind the whole time. By the end the dashboard felt like a real product, not a class demo.

The task improved my understanding of HTML, CSS and JavaScript, state management, input validation, loading and error states, responsive design, transition animation and perceived performance.
